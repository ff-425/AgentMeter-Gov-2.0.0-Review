# AgentMeter-Gov 审批记忆机制 V1

## 目标

人工复核不能每次都让人重复确认。V1 机制把人工审批结果沉淀为受限记忆，用来降低重复低中风险操作的打扰，同时保留审计证据。

V1.1 增强了审批释放边界：

- 审批通过只释放一个完整动作指纹。
- 动作名称、动作族、目标、邮件收件人和参数 hash 任一变化，都必须重新复核。
- 审批记忆只用于低/中风险重复降噪，不用于高风险自动放行。

核心原则：

- 记忆不是信任用户，而是记住“相似场景曾被批准或拒绝”。
- 记忆只能影响低中风险重复操作。
- 硬风险永远不能通过记忆绕过。

## 当前实现

新增模块：

- `agentmeter_gov/review_memory.py`

新增数据文件：

- `data/review_memory.json`

OpenClaw 插件增强：

- 审批通过后写入一条 `approved` 记忆。
- 审批拒绝后写入一条 `rejected` 记忆。
- 审批令牌包含 `signature` 和 `paramsHash`，只能被完全相同的工具调用消费一次。
- 通过记忆默认 7 天有效，最多使用 2 次。
- 拒绝记忆默认 30 天有效，用于相似操作加风险。

## 决策逻辑

原始流程：

```text
工具调用 -> 风险计量 -> human_review / block / allow
```

增强后：

```text
工具调用
  -> 基础风险计量
  -> 查询审批记忆
  -> 查询用户习性画像
  -> 动态修正风险分
  -> allow / human_review / block
```

## 通过记忆

如果某个操作曾经被批准，例如：

```text
读取 internal/tickets.csv，并复制到 tmp/tickets_copy.csv，作为内部备份，不外发。
```

后续相似操作会从：

```text
human_review
```

降为：

```text
allow（保留风险分、命中规则和完整审计）
```

这表示允许执行，但必须完整写入审计日志。

## 拒绝记忆

如果某个操作曾经被拒绝，例如：

```text
读取通讯录，并生成外部上传文件。
```

后续相似操作会增加风险分，可能从 `human_review` 升级为 `block`。

## 安全边界

以下场景不能被审批记忆自动放行：

- 关闭或绕过 AgentMeter-Gov 防护。
- 读取 token、密钥、`.env`、`.npmrc`。
- 删除、清空、覆盖审计日志。
- 合同、验收意见、公文结论等正式文件篡改。
- 敏感数据外发到外部邮箱、URL 或上传目标。

## 当前验证结果

已完成：

- Python 风险引擎编译通过。
- OpenClaw 插件 JS 语法检查通过。
- 73 个政企样本离线回归测试通过。
- 单元验证：重复且上下文完全匹配的已审批场景可从 `human_review` 调整为 `allow`，但继续记录风险分、审批记忆依据和完整审计。
